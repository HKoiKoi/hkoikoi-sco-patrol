## 1. 문제 (Problem)

1. **반복 기록의 번거로움**: 30분 간격 순찰마다 스탠딩·카페존·졸음/딴짓·자리비움 좌석과 특이사항을 정리해 구글 시트에 한 줄씩 옮겨 적어야 한다.
2. **입력 유실 위험**: 순찰 중 기록하다 앱을 닫거나 기기를 바꾸면 작성하던 내용이 사라진다.
3. **기록 형식 불일치**: 시트에 적는 문구가 사람마다 달라 일관성이 떨어진다.
4. **팀 현황 파악 곤란**: 다른 매니저의 순찰 결과를 한곳에서 시간순으로 보기 어렵다.
5. **사후 정정 곤란**: 자리비움 학생의 사후 확인이나 입력 실수를 확정 기록에 반영할 방법이 마땅치 않다.

**기존 대안**: 구글 스프레드시트에 직접 입력, 메신저 메모.

## 2. 고객 세그먼트 (Customer Segments)

| 구분                             | 설명                                                             | 핵심 니즈                                  |
| -------------------------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| **매니저 (`manager`)** (주 고객) | SCO 관리형 독서실에서 순찰을 수행하는 직원. 스마트폰·태블릿 사용 | 이동 중 최소 터치 입력, 시트 붙여넣기 편의 |
| **관리자 (`admin`)**             | 매니저를 관리하고 기록 정정·퀵 태그를 운영하는 담당자            | 팀 기록 정정, 현장 변화에 맞춘 태그 운영   |
| **열람자**                       | 비로그인 방문자, 승인 전 가입자(`pending`)                       | 로그인 없이 일지 조회                      |

**초기 타깃**: 단일 지점 1곳의 순찰 매니저 (다중 지점은 MVP 이후).

## 3. 가치 제안 (Unique Value Proposition)

> **"순찰은 터치 몇 번으로 기록하고, 결과는 한 줄로 복사해 시트에 바로 붙여넣는다."**

- 매니저: 숫자 키패드와 퀵 태그로 입력하고, 1초 자동 저장으로 폰에서 시작한 기록을 태블릿에서 이어 쓴다.
- 관리자: 팀 전체 일지를 영업일별로 보고, 입력 실수와 자리비움 처리를 바로잡는다.
- 열람자: 로그인 없이 URL만으로 현재 순찰 현황을 확인한다.

**상위 개념(High-Level Concept)**: 스프레드시트 기반 순찰 기록을 모바일 우선으로 바꾼 "순찰 입력 + 일지 공유" 앱.

## 4. 해결책 (Solution)

| 문제                 | 해결책                                                                                                | 관련 기능 |
| -------------------- | ----------------------------------------------------------------------------------------------------- | --------- |
| 반복 기록의 번거로움 | 4종 좌석 상태 키패드·칩 입력, 퀵 태그 탭으로 메모 추가, 순찰 완료 버튼                                | F02~F05   |
| 입력 유실            | 약 1초 디바운스 서버 자동 저장, 기기 무관 초안 복원, 오프라인 시 로컬 임시 백업, 충돌 감지            | F07       |
| 형식 불일치          | `lib/patrol-format.ts`가 만드는 한 줄 복사 문구 (예: `22:57 순찰 → 완료 (퇴실자 탭 디스플레이 종료)`) | F06       |
| 팀 현황 파악         | 영업일별 공개 타임라인 조회 (`/logs`), 날짜 이동                                                      | F08       |
| 사후 정정            | 본인(또는 관리자)의 기록 수정·삭제, 자리비움 번호를 스탠딩/카페존으로 이동하거나 삭제                 | F09, F10  |
| 현장 업무 변화       | 관리자 전용 퀵 태그 추가·수정·순서·노출·삭제                                                          | F11       |

**MVP 제외**: 통계/리포트, 다중 지점, 30분 리마인더 알림, 좌석 배치도 UI, 실시간 공동 편집, 관리자 역할 지정 화면.

## 5. 경쟁우위 (Unfair Advantage)

범용 체크리스트·메모 앱이나 시트 직접 입력과 달리, 아래 요소는 쉽게 복제하기 어렵다.

- **현장 맞춤 복사 문구**: 실제 사용 중인 시트 입력 형식(`HH:mm 순찰 → 완료 (...)`)을 그대로 재현한다.
- **관리자가 직접 운영하는 퀵 태그**: DB 수정 없이 현장 업무 변화에 맞춘다.
- **견고한 데이터 무결성**: `revision` 기반 충돌 감지, 요청 ID 멱등 처리, 단일 트랜잭션 완료로 입력 유실·중복 기록을 막는다.
- **DB 중심 권한 모델**: RLS·컬럼 GRANT·RPC 본문 역할 검사를 최종 방어선으로 둔다.
- **운영 현실 반영**: 04:00(KST) 영업일 경계, 방치 초안 자동 정리, 공용 태블릿을 고려한 로그아웃 시 로컬 백업 삭제.
- **(가정)** 현장 운영 경험을 가진 개발자가 직접 만든 도구라 요구사항 반영이 빠르다.

## 6. 수익 흐름 (Revenue Streams)

- **직접 수익 없음 (가정)**: PRD는 SCO 관리형 독서실의 내부 업무 도구 MVP로 정의되어 있고 과금 모델이 없다.
- **간접 가치**: 순찰 기록·복사 시간 절감, 기록 누락·오입력 감소.
- **MVP 이후 검토 가능**: 다중 지점 확장 시 지점별 구독, 통계/리포트 기능 유료화. 이는 PRD에 없는 가설이며 검증이 필요하다.

## 7. 비용 구조 (Cost Structure)

| 구분                   | 내용                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| **개발 비용**          | 1인 개발 인력(Next.js 16, Supabase, Tailwind CSS v4, shadcn/ui), 개발 도구                                |
| **인프라 (고정/변동)** | Supabase(Postgres, Auth, `pg_cron`), 웹 호스팅, HTTPS 도메인. 사용량이 작아 낮은 수준일 것으로 예상(가정) |
| **운영 비용**          | `pending` 사용자의 승격을 Supabase 대시보드에서 수동 처리하는 관리 시간                                   |
| **유지보수**           | 정확한 버전 고정 패키지의 의도적 업그레이드, 실기기(iOS Safari·Android Chrome) 검증                       |

## 8. 주요 지표 (Key Metrics)

PRD에는 지표가 정의되어 있지 않으므로 아래는 제안안이다 **(가정)**. 목표 수치는 도입 전 현재 방식을 측정한 뒤 정한다.

| 구분       | 지표                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| **활용도** | 일일 순찰 완료 건수, 순찰 작성 활성 매니저 수, 기록 작성 주기 준수율(30분 간격) |
| **효율**   | 순찰 1회당 입력·복사까지 걸린 시간, 퀵 태그 사용 비율                           |
| **품질**   | 사후 수정·삭제 건수, 자동 저장 충돌 발생 건수, 복사 실패(대체 입력란 노출) 비율 |
| **채택**   | 시트 직접 입력 대비 앱 사용 비중, 일지 조회 방문 수                             |
| **운영**   | `pending` → `manager` 승격 처리 소요 시간                                       |

## 9. 채널 (Channels)

- **직접 안내**: 소속 매니저·관리자에게 URL 공유와 현장 교육. 대상이 한정된 내부 도구라 대규모 마케팅은 필요 없다 (가정).
- **일지 URL 공유**: 비로그인 열람이 가능하므로 링크만으로 팀·관련자에게 현황을 공유한다.
- **홈 화면 바로가기**: 스마트폰·태블릿 브라우저에 북마크/바로가기를 추가해 접근성을 높인다 (가정).
- **로그인 경로**: Google 로그인과 이메일 가입. 카카오톡 등 인앱 브라우저는 Google 로그인이 차단될 수 있어 외부 브라우저 안내를 제공한다.
- **피드백 경로**: 매니저·관리자의 현장 의견을 퀵 태그 운영과 기능 개선에 반영한다 (가정).

## 핵심 가정 및 검증 필요 사항

1. 매니저가 시트 직접 입력보다 이 앱을 더 빠르다고 느끼는가 → 도입 전후 소요 시간 비교.
2. 로그인 없이 공개되는 일지(좌석 번호·메모·작성자 이름)를 운영상 수용할 수 있는가 → PRD에서 수용하기로 한 정책이나 정기 점검이 필요하다.
3. 수동 승인 방식이 가입자 증가에도 감당 가능한가 → 승격 요청 건수 추적, 부담이 커지면 역할 지정 화면을 검토한다.
4. iOS Safari·Android Chrome, 인앱 브라우저에서 복사와 이메일 확인 링크가 안정적으로 동작하는가 → 실기기 확인.
5. 단일 지점 이후 다중 지점 수요와 과금 가능성이 있는가 → MVP 사용 데이터로 판단.
